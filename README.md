# Конфигурационное управление · ПР №2 · Вариант 2

Python 3.10+. Сборка не требуется. Тесты: `python -m unittest discover -s tests`.

### 1. Конфигурация и ошибки параметров

```sh
python -m src -p openpyxl -d 2 -f dev --show-config
```

Код завершения: `0` — успех, `2` — ошибка аргументов, `1` — ошибка данных,
сети, рендера или записи. Сообщения об ошибках выводятся в stderr.
Примеры неверных параметров; каждое сочетание приведено для отдельного запуска:

| Что проверить | Аргументы после `python -m src` |
| --- | --- |
| Пустое или недопустимое имя | `-p bad/name` |
| Не HTTP(S) URL | `-p demo -r ftp://example.org` |
| Файл не найден в тестовом режиме | `-p A -t -r missing.json` |
| Флаг режима не принимает значение | `-p A --test-mode=yes` |
| Неверный формат изображения | `-p demo -o graph.svg` |
| Недопустимая глубина | `-p demo -d -1` |
| Фильтр из пробелов | `-p demo -f "  "` |

### 2. Прямые зависимости PyPI

```sh
python -m src -p python-docx --direct-only
```

Программа читает `GET /pypi/{name}/json`, поле `info.requires_dist`.
Каждое объявление даёт имя пакета: регистр не учитывается, группы `.`, `_`, `-`
заменяются одним дефисом. Отсутствующий или равный `null` список означает лист.
Сбой сети, HTTP 404 или неверный JSON — ошибка, а не пакет без зависимостей.

### 3. DFS без рекурсии: глубина, фильтр и циклы

Файл `examples/repository.json` содержит объект вида `{"A": ["B"], "B": []}`.
Имена — заглавные латинские буквы. Упомянутую только справа вершину допустимо
не объявлять: это лист. Незнакомое имя начального пакета считается ошибкой.
В примере `D -> B -> D` — цикл, `G` изолирован, `F -> D` даёт внешний вход.

```sh
python -m src -p A -t -r examples/repository.json -d 0 --graph-only
python -m src -p A -t -r examples/repository.json -d 1 --graph-only
python -m src -p A -t -r examples/repository.json -d 8 -f C --graph-only
```

В первом запуске видна только `A`, во втором — `A -> B` и `A -> C`.
В третьем остаются `A -> B`, `B -> D` и `D -> B`; ветвь через `C` исключена.
DFS использует явный стек. Если найден более короткий путь к вершине,
её потомки проверяются снова с новым остатком глубины. Ребро цикла сохраняется,
но проход с равной или большей глубиной не повторяется. Запросы PyPI кэшируются.

### 4. Обратные зависимости

```sh
python -m src -p D -t -r examples/repository.json --reverse -d 1
python -m src -p D -t -r examples/repository.json --reverse -d 2
python -m src -p G -t -r examples/repository.json --reverse
python -m src -p et-xmlfile --reverse --scope openpyxl -d 1
```

Результаты: `B, C, F`; затем `A, B, C, F`; для `G` список пуст; в последнем
примере — `openpyxl`. Используется тот же DFS после обращения направления рёбер.
В тестовом файле поиск идёт по всему репозиторию. Для PyPI область задаётся
явно: сначала строится объединение графов от `--scope` до `--max-depth`, затем
ищутся потребители внутри этого объединения. Это **не** поиск по всему PyPI.
