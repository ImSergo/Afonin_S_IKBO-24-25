# Визуализация графа зависимостей Python (вариант №2)

## 1. Общее описание

CLI-программа показывает, от каких пакетов Python зависит выбранный пакет.
Источником данных может быть PyPI или локальный тестовый файл. Программа
строит граф обходом DFS без рекурсии и сохраняет его в PNG через Graphviz.

Стрелка `A -> B` означает: «пакет A зависит от пакета B». Программа получает
метаданные из PyPI напрямую; pip и сторонние библиотеки для этого не используются.

## 2. Параметры программы

| Опция | Описание |
| --- | --- |
| `-p`, `--package` | Имя пакета, с которого начинается анализ. Обязательно. |
| `-r`, `--repo` | Адрес PyPI-совместимого API или путь к JSON-файлу. По умолчанию: `https://pypi.org/pypi`. |
| `-t`, `--test-mode` | Читать граф из файла, указанного в `--repo`. |
| `-o`, `--output` | Имя PNG-файла. Рядом сохраняется DOT-файл. По умолчанию: `graph.png`. |
| `-d`, `--max-depth` | Максимальное число переходов по зависимостям. По умолчанию: `3`. |
| `-f`, `--filter` | Исключить пакеты, чьё имя содержит эту подстроку. |
| `--show-config` | Показать заданные параметры в формате `ключ=значение`. |
| `--direct-only` | Вывести только прямые зависимости пакета. |
| `--reverse` | Найти пакеты, которые зависят от указанного пакета. |
| `--scope NAME` | Задать корень поиска обратных зависимостей PyPI. Можно указать несколько раз. |
| `--graph-only` | Вывести Graphviz DOT, не создавая изображение. |

Режимы `--show-config`, `--direct-only`, `--reverse` и `--graph-only`
взаимоисключающие. Если режим не задан, программа строит граф и PNG.
При глубине `0` отображается только начальный пакет. Фильтр применяется ко
всем именам без учёта регистра. Циклы остаются видны на графе, но не приводят
к бесконечному обходу.

Для обратного поиска по PyPI укажите `--scope`. Поиск выполняется только
внутри этой области. В тестовом режиме областью служит весь файл.

## 3. Запуск, Graphviz и тесты

Требуется Python 3.10 или новее. Устанавливать Python-библиотеки не нужно.
Для PNG нужен Graphviz (`dot`). На Windows установите Graphviz и добавьте
папку `bin` в `PATH`. Если программа не находит Graphviz автоматически,
задайте переменную `GRAPHVIZ_DOT` с путём к `dot.exe`.

Откройте PowerShell в папке проекта и запустите тесты:

```powershell
.\run.bat test
```

Сборка проекта не требуется. Справка по командам:

```powershell
.\run.bat --help
```

## 4. Примеры использования

### Этап 1. Проверка параметров

Показать настройки:

```powershell
.\run.bat -p openpyxl -d 2 -f dev --show-config
```

Проверить обработку неверной глубины:

```powershell
.\run.bat -p openpyxl -d -1
```

Программа также проверяет имя пакета, адрес репозитория, наличие тестового
файла и расширение выходного изображения.

### Этап 2. Прямые зависимости из PyPI

```powershell
.\run.bat -p python-docx --direct-only
```

Программа читает метаданные пакета на PyPI и выводит прямые зависимости.
В этом примере это `lxml` и `typing-extensions`. Нужен доступ к интернету.

### Этап 3. Граф, глубина, фильтр и циклы

Тестовый граф находится в `examples/repository.json`. Формат — JSON-объект:
имя пакета и список его зависимостей. Например, `"A": ["B"]` означает, что
A зависит от B. Имена тестовых пакетов записываются заглавными латинскими
буквами.

Показать только начальный пакет:

```powershell
.\run.bat -p A -t -r examples/repository.json -d 0 --graph-only
```

Показать прямые связи пакета A:

```powershell
.\run.bat -p A -t -r examples/repository.json -d 1 --graph-only
```

Исключить пакеты с буквой C в имени:

```powershell
.\run.bat -p A -t -r examples/repository.json -d 8 -f C --graph-only
```

В примере есть цикл `B -> D -> B`. DFS использует стек вместо рекурсивных
вызовов: цикл виден в графе, а обход при этом завершается.

### Этап 4. Обратные зависимости

Найти пакеты, которые напрямую зависят от D:

```powershell
.\run.bat -p D -t -r examples/repository.json --reverse -d 1
```

Результат: `B`, `C` и `F`. Увеличить глубину поиска:

```powershell
.\run.bat -p D -t -r examples/repository.json --reverse -d 2
```

При глубине `2` добавится `A`: он зависит от D через B или C.

Для поиска в PyPI задайте область. Например, найти потребителей
`et-xmlfile` среди зависимостей `openpyxl`:

```powershell
.\run.bat -p et-xmlfile --reverse --scope openpyxl -d 1
```

### Этап 5. Создание DOT и PNG

```powershell
.\run.bat -p python-docx -d 1 -o output/python-docx.png
.\run.bat -p openpyxl -d 1 -o output/openpyxl.png
.\run.bat -p et-xmlfile -d 1 -o output/et-xmlfile.png
```

Для каждого запуска программа сохраняет PNG и текстовое описание графа DOT.
Файлы создаются в указанной папке.

## 5. Сравнение с pip

Сравнены прямые зависимости из графа и поле `Requires` команды
`python -m pip show`. Глубина анализа — `1`.

| Пакет | Зависимости графа | Результат `pip show` |
| --- | --- | --- |
| `python-docx 1.2.0` | `lxml`, `typing-extensions` | `lxml`, `typing_extensions` |
| `openpyxl 3.1.5` | `et-xmlfile` | `et-xmlfile` |
| `et-xmlfile 2.0.0` | Нет | Нет |

После нормализации имён результаты совпали. В общем случае результаты могут
различаться: граф показывает зависимости из метаданных PyPI, а pip — сведения
об установленной версии. Условные зависимости и extras могут быть объявлены,
но не использоваться в конкретной среде. Программа не подбирает версии пакетов.
